# Spec 6 — Reliability Gate and Causal Manipulation (E3)

Oct 22, 2026 · @Jekaterina

## Purpose

This spec runs E3: it builds two altered versions of high-I, high-S items, checks with Jev that each alteration moved the intended score, and tests H5 and the causal claim with paired comparisons under both proxies. It is Step 6 of protocol v1 and the last non-optional step.

Three variants of the high-I, high-S cell are compared with their originals:

- **Corrupted** (`#corrupt`): the answer becomes a wrong number that still looks determinate. Tests H5, that confident but false labels have negative value.
- **Premise-deleted** (`#premdel`): one context sentence the answer does not depend on is removed, while the answer stays correct. Tests whether implication strength matters causally.
- **Low-R**: naturally occurring high-I, high-S items that Jev judges unreliable. A secondary check of H5 without construction.

**Gating.** The `e3` stage reads `results/gates.json` and exits if `derived.halt` is true. It also exits if `derived.halt_spec6` is true, unless `derived.halt_spec6_override` holds a written reason.

**Inputs.** `data/analysis_frame.parquet` and `gates.json` (Spec 3); `pool.parquet`, `q3_checks.parquet` and the shared helpers (Spec 1); `answer_nll` (Spec 2); `compute_influence`, `run_condition` and the `random` condition's runs (Specs 4–5). **Outputs.** `data/e3_items.parquet`, `scores/jev_scores_e3.parquet`, `scores/surprisal_e3.parquet`, `results/e3/`, and the H5 and causal rows of `results/hypotheses.csv`.

## Base items

The corrupted and premise-deleted variants are built from one shared sample of originals, so every comparison with the original is paired item by item. Low-R items cannot be paired, since they are different items, and are compared at the group level.

**Originals.** From analysis-frame rows with `cell = hiI_hiS` **and `R_eff ≥ r_threshold`**, sample up to 300 per dataset with `stable_seed(global_seed, "e3_base")`, stratified by `answer_type`. If D1 fired, `arith` items are kept; corruption and premise deletion do not depend on R. Store the list as `conf/e3_base.yaml`. Items that fail variant construction (next section) are dropped from both variants, so the two variant sets share the same base items.

The reliability condition is stated separately from the cell because `cell` stops implying it when gate D4 has set `cells_r_filter = false`: `in_design` is then true for every item, so `hiI_hiS` includes unreliable rows. H5 is a claim about corrupting *high-R* originals, so the base sample must carry the condition itself rather than inherit it from the cell. When `cells_r_filter` is true the condition is redundant and changes nothing.

**Low-R items.** Frame rows with I and S above the dataset's `gates.json` medians and `R_eff` below `r_threshold`. If D1 fired, only `lookup` rows qualify, since effective R is 1 for verified `arith` rows. If `cells_r_filter` is false, use rows with I and S above the medians and `R_eff` both in the dataset's lowest 20% and below `r_threshold`, the second condition being what keeps the low-R set disjoint from the base originals when the lowest quintile reaches above the threshold. Use all qualifying rows; there is no top-up, as the protocol specifies naturally occurring items.

Base originals and low-R items are therefore disjoint under every gate outcome, which the stage asserts before building variants. Were they to overlap, an item could serve as both its own manipulation baseline and a member of the group it is contrasted against.

**Minimum sizes.** A variant enters the C analysis for a dataset only if it has at least 20 items there, the floor `run_condition` enforces. The G analysis has no floor but reports n. If low-R has fewer than 20 items in both datasets, it is reported descriptively and gets no verdict.

## Variant construction

Each base item yields one corrupted and one premise-deleted variant. Both are deterministic given `stable_seed`, and both reuse Spec 1 code rather than adding new perturbation logic.

**Corrupted (`#corrupt`).** Call `make_wrong_answer(item, tag="corrupt")`, the function Spec 1 uses for its `#neg` items, now shared in `fqsel/perturb.py`. The different tag gives a different random draw. Two extra constraints apply, so that the wrong answer looks determinate and is not accidentally supported:

1. The new value keeps the gold's precision, units and format (percent stays percent, thousands separators kept).
2. The new value must not appear anywhere in the context after number normalization; otherwise redraw, up to 5 times, then drop the base item.

The Q3 check is regenerated by Spec 1's generator with the corrupted answer passed as the answer, `generate_check(item, answer=new)`. Context and question are unchanged.

**Premise-deleted (`#premdel`).** Remove exactly one context sentence that the answer does not depend on:

1. Split the context into sentences with one pinned splitter (pysbd, fixed version), the same for both datasets.
2. Candidates are sentences outside the support set: for FinQA, not among the `text_*` keys of `gold_inds`; for TAT-QA, not in a paragraph listed in `rel_paragraphs`. Table rows are never deleted.
3. Exclude candidates containing the gold answer string, or any numeric argument of the FinQA program or TAT-QA derivation.
4. Of the remaining candidates, delete the one with the highest Jaccard overlap of lowercased content words with the question, breaking ties with `stable_seed(item_id, "premdel")`. This removes the most question-relevant corroborating sentence, which is the deletion most likely to lower determinacy without touching the answer.
5. Re-run verification from Spec 1 on the modified item; if it fails, or no candidate exists, drop the base item.

The gold answer and Q3 check are unchanged. Store `deleted_sentence` for audit.

**Schema.** `data/e3_items.parquet` uses the pool schema plus `variant` (corrupt or premdel), `original_answer` and `deleted_sentence`, with `is_derived = true` and `base_item_id` set. The item lookup in `fqsel/io.py` unions this table with `pool.parquet`, so the Spec 4 engines accept variant IDs without changes. Low-R items are pool originals and need no new rows.

## Manipulation check

Each constructed variant must move the intended score before its results can support any claim. Corruption should lower reliability much more than implication; premise deletion should lower implication more than reliability. The criteria below are fixed before any variant is scored.

**Scoring.** Score every variant with all six Jev questions, using Spec 1's client, cache and prompts unchanged. The stage refuses to run if Spec 1's `battery_version` differs from the one in `gates.json`. Write results to `scores/jev_scores_e3.parquet` in the `jev_scores` schema. Also compute each variant's answer NLL with `answer_nll`, and map it to a percentile of its dataset's pool distribution, for description only.

**Paired differences.** For each base item, ΔR = R(variant) − R(original) and ΔI = I(variant) − I(original). Tests are one-sided Wilcoxon signed-rank tests over base items, pooled across datasets, at α = 0.01.

| Variant | Passes when both hold | Reported alongside |
| --- | --- | --- |
| Corrupted | Median ΔR ≤ −0.2 and ΔR < 0 is significant; ΔI − ΔR > 0 is significant, so implication falls less than reliability | ΔQ3 alone, since Q2 may also fall when the answer is wrong |
| Premise-deleted | ΔI < 0 is significant; ΔR − ΔI > 0 is significant, so reliability falls less than implication | Verification status, which is unchanged by construction |

Low-R items are not constructed and have no manipulation check. Their mean R, I, S and acc are reported beside those of the originals.

**Consequence of a failure.** A failed check does not stop the stage: the variant's analyses still run and are reported. Its verdicts, however, are recorded as `manipulation_failed`, and the paper makes no claim from that variant. A failed premise deletion would itself be informative, since it would mean removing corroborating context does not reduce Jev's sense of determinacy.

## Analysis under G

Under G, each variant is compared with its own original, so differences in topic, length or dataset cancel out. Three primary contrasts form one Holm family at α = 0.05, one-sided, matching the protocol's three E3 contrasts.

**Computation.** Call `compute_influence` on all variant IDs. The stage asserts that the LoRA and projection seeds equal those stored with the pool's G in `influence.parquet`; a mismatch is an error, since the G values would not be comparable.

| Contrast | Test | Effect reported |
| --- | --- | --- |
| Corrupted vs original | Paired Wilcoxon on ΔG = G(corrupt) − G(original), alternative ΔG < 0 | Median ΔG |
| Premise-deleted vs original | Paired Wilcoxon on ΔG, alternative ΔG < 0 | Median ΔG |
| Low-R vs originals | Mann–Whitney, G(low-R) against G of the sampled originals, alternative lower | Difference in medians |

**Second H5 condition.** The protocol also requires corrupted items to sit below the pool median of G. Test it with a one-sample Wilcoxon on G(corrupt) minus the frame's median G, one-sided, at α = 0.05. It is a conjunctive condition, not part of the Holm family, since requiring two tests to pass cannot raise the false-positive rate.

**Uncertainty.** Intervals for the median effects come from the joint bootstrap of Spec 5, 1,000 replicates: resample probe vectors and recompute ḡ and G for originals and variants together, then resample base items. Report each contrast overall and per dataset, and repeat with `G_dot` as a robustness check.

## Analysis under C

Under C, the corrupted and premise-deleted conditions reuse the original condition's draws item for item: draw j of each uses the variants of exactly the base items drawn for the original. This makes demonstration sets differ only by the manipulation, which removes draw-to-draw noise from those contrasts.

**Conditions.** Four, 50 draws each, through `run_condition`:

| Condition | Demonstrations in draw j |
| --- | --- |
| `e3_orig` | 4 base originals per dataset, sampled with `stable_seed(global_seed, "e3", j)` |
| `e3_corrupt` | The `#corrupt` variants of exactly those base items |
| `e3_premdel` | The `#premdel` variants of exactly those base items |
| `e3_lowR` | 4 low-R items per dataset, sampled independently with `stable_seed(global_seed, "e3_lowR", j)` |

The three paired conditions are written with an explicit `demo_plan` (draw → demonstration IDs per dataset) instead of an eligible list, which Spec 4's `run_condition` accepts. Demonstration order is the same across the three for each draw. CBI sampling follows Spec 4.

**Models,** on in-distribution test items, estimated as in Spec 5 (E1-C, Estimation): test-item fixed effects in `fe_logit`, with the two-way cluster bootstrap over test items and draws.

- Paired contrasts, on `e3_orig`, `e3_corrupt` and `e3_premdel`: `correct ~ variant + dataset + (1 | test_item) + (1 | draw)`. The draw term is crossed rather than nested, because the three conditions share draws; in the bootstrap, each resampled draw index j is taken for all three conditions together, which preserves the pairing.
- Low-R contrast, on `e3_orig` and `e3_lowR`: `correct ~ condition + dataset + (1 | test_item) + (1 | condition:draw)`, with draws resampled separately within each condition.

The three contrasts against `e3_orig` (corrupted, premise-deleted, low-R) form the Holm family, one-sided, α = 0.05.

**Second H5 condition.** The protocol states H5 under C as corrupted demonstrations reducing accuracy relative to `random`. Fit `correct ~ condition + dataset + (1 | test_item) + (1 | condition:draw)` on `e3_corrupt` and Spec 5's `random` runs; one-sided, α = 0.05, conjunctive with the paired contrast.

FinanceBench results follow Spec 4's rule: tested only if at least 50 items survived filtering, otherwise descriptive.

## Verdicts, outputs and cost

Verdicts are written only through `record_verdict`, one row per key × proxy, and each names the rule applied. A variant whose manipulation check failed gets `manipulation_failed` under both proxies, whatever its test results.

| Key | Proxy | Supported when |
| --- | --- | --- |
| H5 | G | Corrupted check passed; corrupted vs original significant after Holm; corrupted G below the pool median |
| H5 | C | Corrupted check passed; corrupted vs original significant after Holm; corrupted below `random` |
| H5 | overall | Supported under both. If supported under G but not C, record `supported_G_only`, which the protocol treats as interpretable rather than contradictory, given the known insensitivity of demonstrations to label correctness. |
| E3\_causal | G, C, overall | Premise-deletion check passed and premise-deleted vs original significant after Holm; overall requires both proxies |
| E3\_lowR | G, C | Low-R vs original significant after Holm; secondary, and descriptive only if fewer than 20 low-R items in both datasets |

If `derived.single_proxy_claims` is false (gate D6), overall verdicts are recorded but the G-only and C-only rows must be reported together in the paper.

**Output tables.** `results/e3/manipulation.csv`, `results/e3/g_contrasts.csv` and `results/e3/c_contrasts.csv`, in the Spec 3 schema plus `hypothesis` and `supported`. Item-level paired data go to `results/e3/paired_items.parquet`, with base item, variant, ΔR, ΔI, ΔG and the deleted sentence or new answer.

**Figure.** Fig. 4 has two panels. Left: ΔG per base item for the corrupted and premise-deleted variants, as paired dot strips with median and interval. Right: accuracy for `e3_orig`, `e3_corrupt`, `e3_premdel`, `e3_lowR` and `random`, with bootstrap intervals over draws.

**Cost.** About 600 base items give 1,200 variants: roughly 7,200 Jev calls, 1,200 gradient passes, and 4 conditions × 50 draws × about 1,000 test items, roughly 200,000 greedy generations plus CBI samples on 10 draws. On the same node as Spec 4, that is a few hours.

## Acceptance tests and open items

Spec 6 is done when these pass on the tiny profile and on a 50-base-item pilot, before the full run.

- [ ] Gating: the stage exits when `halt` or `halt_spec6` is true, and runs when `halt_spec6_override` holds a reason.
- [ ] Every corrupted answer fails `answers_match` against the gold, keeps the gold's precision and units, and does not occur in the context.
- [ ] Every premise-deleted item differs from its original by exactly one sentence, outside the support set and containing no program argument or the gold answer, and still passes verification.
- [ ] The corrupted and premise-deleted sets have identical base item lists.
- [ ] Every base original has `R_eff ≥ r_threshold`, and no base original is also a low-R item. Both hold in a test with a synthetic `gates.json` in which D4 has set `cells_r_filter = false`, where `cell` alone would admit unreliable rows.
- [ ] In each draw j, `e3_corrupt` and `e3_premdel` use the variants of exactly the base items `e3_orig` uses, in the same order.
- [ ] In every bootstrap replicate of the paired contrasts, the three conditions carry the same multiset of draw indices.
- [ ] Variant G values come from the same LoRA and projection seeds as the pool's; a test with mismatched seeds raises an error.
- [ ] Jev scores for variants share the pool's `battery_version` and model version, and cached calls for originals are not re-sent.
- [ ] A planted-effect simulation (paired ΔG with median −0.05) is detected in at least 90% of 200 runs, and a null simulation rejects in at most 7%.
- [ ] On a synthetic manipulation table with a failed check, the verdict is `manipulation_failed` regardless of the contrast results.
- [ ] No `e3_*` item appears in any Spec 5 condition file, and Spec 5 results are unchanged when Spec 6 runs.

**Open items.**

- Pin the pysbd version, and confirm on 50 items per dataset that its sentence boundaries match the FinQA sentence indices used in `gold_inds`.
- Spec 1 and Spec 4 now carry the matching edits: `make_wrong_answer` and `generate_check(item, answer=…)` exposed as shared helpers, `e3_items.parquet` in the file layout, and `demo_plan` accepted by `run_condition`.
